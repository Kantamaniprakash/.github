# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in any of my repositories, please report
it responsibly rather than opening a public issue.

- **Preferred:** Open a [GitHub private vulnerability report](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
  via the **Security** tab of the affected repository.
- **Alternative:** Email **prakash.kantamani@gmail.com** with the details.

Please include:

- The repository and affected version/commit
- A description of the issue and its potential impact
- Steps to reproduce, or a proof of concept

### What to expect

- **Acknowledgement:** within 3 business days
- **Assessment & triage:** within 7 business days
- **Fix or mitigation plan:** communicated once the issue is confirmed

These are personal / portfolio projects maintained by a single author, so timelines
are best-effort. I appreciate coordinated disclosure and will credit reporters who
wish to be acknowledged.

## Supported Versions

Unless a repository states otherwise, only the latest commit on the default branch
is supported. Fixes are applied to the default branch and, where applicable, a new
tagged release is cut.
